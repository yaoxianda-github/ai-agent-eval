AI Agent 评测平台 · 操作手册

给 Agent 出题、批改、打分，一页讲明白

本手册写给从没接触过 Agent 评测的初级测试工程师。你不需要懂大模型原理，也不需要会写复杂代码——跟着步骤走，就能完成第一次评测，并理解每个表单参数的含义。

适用：ai-agent-eval 工作台 版本：V2.2 前置：Python 3.9+ 环境 耗时：约 10 分钟上手
一句话理解这个平台

评测平台 = 给每个 AI Agent「出一套题」，让它在一个干净的工作目录里完成，再按「批改清单」逐条核对产物，最后给出一份带证据的得分报告。

01

评测平台是什么

先建立整体概念，再动手。这一节回答三个问题：评测的完整流程、四个关键概念、零基础最常见的顾虑。

一次评测的完整流程

整个评测可以拆成五个环节，每一步都有产物、可追溯：

01
任务包
任务描述 + 初始文件 + 批改清单
→
02
评测引擎
准备干净工作目录，调用 Agent
→
03
Agent 执行
读任务、操作文件、产出结果
→
04
判定批改
按校验点核对产物，逐条 PASS / FAIL
→
05
报告
得分 + 轨迹 + 产物，一键出 HTML 报告

四个必须理解的概念

任务 Task

一套「考题」

包含给 Agent 的指令（description）、初始文件（fixtures）、批改清单（checkpoints）和分值权重。任务都放在 tasks/ 目录，一个任务一个文件夹。

后端 Agent

一个「考生」

被测的 AI 助手。平台内置自研的 minimal-react 白盒 Agent，也可接入 aider 等第三方工具。同一套题可以让多个考生各做一遍，横向对比。

校验点 Checkpoint

批改清单的一条

一条可自动执行的判定规则，例如「文件 output/report.md 存在」「内容包含 ERROR_COUNT=3」。全部通过 = 任务通过。

得分 Score

一次考试的结果

得分 = 任务权重 × 校验点通过率。判分依据、步骤轨迹、原始产物全部保留，可一路下钻看证据。

零基础最常见的问题

会不会很复杂？我需要先学大模型知识吗？

不需要。平台把「评测」抽象成了「出题 + 批改」。你只需要：选一个任务 → 点运行 → 看结果。背后的模型调用、沙箱隔离、判分逻辑都由框架处理。

我需要写代码吗？

只是使用：完全不用。工作台全程浏览器操作。如果你以后想自己「出题」（新增任务），只需要填一张表单，平台会自动生成配置文件。

跑一次评测会花很多钱吗？

会消耗少量 LLM API 费用，但成本可控：默认模型 deepseek-chat 很便宜；单任务有成本预算上限（cost_budget_usd，默认 0.5 美元）；采样次数（runs）默认 1 次。第一次体验建议先跑 1 次。

结果靠谱吗？会不会是 Agent「自报成绩」？

不会。判定完全看产物，不看 Agent 自己怎么说——校验点检查的是真实生成的文件内容和命令执行结果。而且多 run 采样会给出多次运行的最好 / 平均 / 波动，把「运气」也暴露出来。

安装与启动

环境准备好后，三步即可打开工作台。以下命令均在终端（Windows 的 CMD 或 PowerShell）执行。

第 1 步：安装框架

# 进入项目目录 cd D:\xdyao\DoubaoWork\projects\ai-agent-eval # 安装开发依赖 + Web 工作台依赖 pip install -e ".[dev]" pip install -e ".[web]"

第一次安装会自动装上 FastAPI、uvicorn 等依赖。若提示失败，确认 Python 版本 ≥ 3.9（命令行执行 python --version 可查看）。

第 2 步：配置 LLM API Key

评测需要调用大模型让 Agent 干活。平台默认使用 DeepSeek，需要你准备一个 API Key。配置后请重开终端再继续。

# Windows（写入用户环境变量，永久生效） setx DEEPSEEK_API_KEY "sk-你的密钥"
没有 Key 也能安装和打开工作台，但「运行评测」会因缺少密钥而失败。平台会如实报错，不会假装成功。

第 3 步：启动工作台

推荐方式（双击即可）：直接双击项目根目录的 start_workbench.bat。或在终端执行：

agent-eval workbench

看到如下输出后，用浏览器打开 http://127.0.0.1:8000 就进入工作台了。

Web 评测工作台启动中: http://127.0.0.1:8000 （Ctrl+C 停止）
也可以换端口启动：agent-eval workbench --port 8080；或直接跑 python -m agent_eval.web --port 8000。关闭终端或按 Ctrl+C 即可停止服务。

04

表单参数详解

这是本手册的重点。「工作台」视图里的每个输入框、下拉框都对应一次评测的关键设置。下面逐个解释：它是什么、怎么选、新手建议。

运行控制台：5 个参数

参数是什么可选值新手建议
任务 要执行的考题（Task），决定 Agent 要完成什么、按什么清单批改。 任务列表，来自 tasks/（当前 6 个：T001/T102/T205/T401/T502/T601） 第一次选 T601，简单直观、费用低。
后端 被测的 Agent（考生）。不同后端能力与风格不同。 minimal-react（自研白盒，记录每一步）· aider（第三方黑盒） 默认 minimal-react 即可，轨迹最完整。
模型 驱动 Agent 的底层大模型名。 默认 deepseek-chat，可换成你 Key 支持的其它模型 保持默认。换模型会改变行为，是评测的「自变量」之一。
超时（秒） 单个 Agent 本次运行的最长时长，超过即强制停止，判为未完成。 覆盖任务默认值（通常 300，T502 为 600，T601 为 120） 不填就用任务默认。任务卡住时，这是兜底保护。
采样次数 同一任务重复运行的次数（runs，1–20）。Agent 有随机性，跑多次才能看出稳定性。 1 – 20，默认 1 体验用 1；正式对比建议 3，可看到 best / mean / std。

命令行等价参数

如果你偏好命令行，同一套设置用 agent-eval run 完成，参数一一对应：

# 完整参数示例 agent-eval run --task T601 --agent minimal-react --model deepseek-chat --timeout 120 --runs 3 # 常用组合：跑 3 次采样看统计 agent-eval run --task T502 --agent minimal-react --runs 3 # 输出示例： # 统计 (N=3): best=0.92 mean=0.88 std=0.05 pass_rate=1.0

这些参数背后的设计意图

为什么要采样

对抗非确定性

同一个 Agent 跑同一道题，结果可能不同。单次成绩可能是「运气」。多跑几次，best 看能力上限、mean 看平均水平、std 看稳定性。

为什么要超时

防止失控拖垮评测

Agent 可能陷入死循环或长时间空转。超时会强制终止该次运行并记录，不会阻塞整批任务。

后端 vs 模型

两个不同的「变量」

后端是 Agent 的思考与工具框架，模型是底层的语言能力。评测时可以固定一个、只改另一个，才能得出可信对比。

成本控制

评测不是烧钱

采样次数、模型选择、任务成本预算共同控制花费。建议先小步验证，再放大采样。

进阶：新建一个任务

会「出题」才算真正会用评测平台。在「任务管理」视图点新建，填一张表单，平台自动生成 spec.yaml、fixtures 骨架，并更新任务清单。

新建任务表单字段

字段必填说明示例
任务 ID必填唯一标识，3–20 位字母/数字/下划线T601
标题必填给人和 Agent 看的简短名称日志错误统计
级别必填难度分层：L1 单步 / L2 多步 / L3 跨工具 / L4 故障注入 / L5 开放式L2
描述选填给 Agent 的完整指令主体，越明确越好读取 input/app.log，统计 ERROR 行数…
标签选填逗号分隔，便于检索data, logging
判定方式必填deterministic 确定性校验；llm_judge 追加 LLM 语义判分（适合开放题）deterministic
校验点至少 1 条批改清单，可动态增删，每条含 id / 类型 / 判定字段c1 file_exists…
权重选填任务得分占比，默认 1.0（T502 用 2.0 提高权重）1.0
成本上限选填cost_budget_usd，预估单次花费上限，默认 0.50.1
超时选填timeout_s，默认 300 秒120
评分标准 rubric选填仅判定方式为 llm_judge 时有效；缺省用内置标准（完整性/准确性/结构/语言）四个章节各占 30/25/25/20 分…

5 种校验点，一张表看懂

校验点是任务的核心。它决定「什么算做对了」。

类型判定逻辑（通过条件）需要填写的字段
file_exists某个文件 / 目录存在path
file_not_exists某个文件 / 目录不存在path
content_contains文件内容匹配指定正则path + pattern
content_not_contains文件内容不包含指定正则path + pattern
cmd_exit_zero执行命令退出码为 0cmd
约定：path 相对 Agent 的工作目录；cmd 中的 @scripts/xxx.py 会被替换成项目 scripts/ 的绝对路径——把复核脚本放仓库里，避免被 Agent 篡改。

一个完整例子：T601 日志错误统计

输入是一份日志，要求 Agent 统计 ERROR 行数并写报告。它的三个校验点正好覆盖了三种典型判型：

# tasks/T601/spec.yaml（节选） description: 读取 input/app.log，统计 ERROR 级别日志行数， 输出 output/errors_report.md，第一行为 ERROR_COUNT=<数量> ground_truth: checkpoints: - id: c1 type: file_exists # ① 产物文件存在 path: output/errors_report.md - id: c2 type: content_contains # ② 内容里有正确计数 path: output/errors_report.md pattern: "ERROR_COUNT=3" - id: c3 type: cmd_exit_zero # ③ 独立复核脚本通过 cmd: "python @scripts/verify_t601.py ." verifier: deterministic

看到 c3 了吗？它用一段独立脚本重新核对报告计数是否和日志真实行数一致——这就是「判定也要被验证」，避免 Agent 写对了格式却没数对数据。

如何阅读运行详情

判定结果 verdict

逐条 PASS / FAIL

每条校验点对应一条判定，带通过状态与说明。所有校验点通过 = 任务通过。

步骤轨迹 steps

Agent 做了什么

白盒后端记录每一步（调用哪个工具、参数、观察结果）。黑盒后端记录单次调用输出。报告会注明口径。

产物预览

看真实文件

工作目录里的产物文件可在线预览。仅支持常见文本类型且 ≤ 200KB，并做了路径穿越防护，安全浏览。

采样统计

多次运行怎么看

N 采样数 · best 最高分 · mean 平均分 · std 标准差（越小越稳）· pass_rate 通过率。

一键生成分享报告

在「报告」视图点击生成，或命令行执行 agent-eval report，会聚合全部运行记录，产出一个自包含的 HTML 报告（reports/report.html），离线也能打开，适合发给同事或放在评审里。

关于语义判分（llm_judge）

像「写周报」这类开放任务，无法用「文件内容匹配」判断质量。此时判定方式选 llm_judge，框架会让 LLM 按 rubric 打分（满分 100 折算成 0–1），输出 score 和 reasoning（判分理由）。

注意：llm_judge 需要 API Key；若缺 Key、判分调用失败或没有产物，该条会如实记为不通过，但不会中断整次评测——这是平台「诚实降级」的设计。
07

常见问题与排障

按「现象 → 原因 → 处理」整理最常见的问题。更详细日志可查看结果目录下的 run.json。

现象可能原因处理
运行报「缺少 LLM API Key」 未配置 DEEPSEEK_API_KEY / LLM_API_KEY 执行 setx DEEPSEEK_API_KEY "sk-..." 后重开终端，再启动工作台。
运行报「未知后端」 后端名称拼写错误或未安装 在下拉框里选存在的后端；aider 需额外 pip install -e ".[aider]"。
运行报「未知任务」 任务 ID 不存在于任务清单 在任务管理确认；任务目录需在 tasks/ 且在 manifest.yaml 中登记。
8080/8000 端口被占用 已有进程监听该端口 换端口：agent-eval workbench --port 8081。
产物预览失败 类型不在白名单，或文件 > 200KB 预览仅支持 md/txt/csv/json/log/py/yaml/yml/xml/html/svg 且 ≤ 200KB；大文件请本地打开。
结果一直 pending / running Agent 卡住或任务耗时长 等待超时强杀（任务默认超时）；或检查网络 / Key 是否有效。
多次运行结果不稳定 Agent 本身有随机性 属正常现象。加大采样次数（runs）看 best / mean / std，不要用单次下结论。
结果都存在哪：每次运行的结果在 results/runs/<run_id>/（含 run.json、workspace 工作目录），SQLite 只是历史索引，原始证据始终是文件。

术语含义
