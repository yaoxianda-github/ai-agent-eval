# Roadshow Deck — Scratchpad（规划，非交付物）

## 场合与语气
- 场合：内部经验分享 + 领导技术汇报。听众：工程师同事 + 技术负责人。
- 身份：主导该项目的测试工程师，向团队汇报"一个可分享、可复用的 AI Agent 评测框架如何从 0 落地到 V2.2"。
- 密度：中（讲清价值 + 关键技术，不贴代码）。标题：主题式短名词短语，直白，不玩金句。

## 视觉方向（frontend-design 四槽位）
- 世界：AI Agent 评测 / 软件测试工程。器物：任务卡片、判定清单、运行日志、报告、刻度仪表。
- 材质：检查清单、刻度尺、日志行、工序编号、轨道节点。
- 配色：
  - `--bg` 纸白 #F6F4EF（浅色正文页底）
  - `--ink` 墨蓝 #16233B（封面/章节深底）
  - `--ink-2` 墨灰 #33415C（正文）
  - `--accent` 青绿 #1F8A70（通过/亮点）
  - `--amber` 琥珀 #C98A2D（进行中/注意）
  - `--muted` #8A93A6（次要）
- 签名元素：「四阶段评测轨道」——一条带 4 节点的水平轨道（MVP→V2.0→V2.1→V2.2），当前页阶段节点高亮，贯穿全 deck，呼应"全链路落地"主线。

## 字体
- 展示/标题：Noto Sans SC 900；正文：Noto Sans SC 400/500；数据/编号：IBM Plex Mono（经 miaoda 镜像拉取）。

## 标题序列（主题式）+ 版式原型 + 视觉锚点
1. 封面 —— 主视觉（轨道/刻度）+ 大标题 —— 锚点：标题
2. 我们要解决的问题 —— 三栏（背景/目标/原则）—— 锚点：核心目标句
3. 全链路总览：MVP→V2.0→V2.1→V2.2 —— 四阶段轨道大图 —— 锚点：轨道
4. MVP：一周最小闭环 —— 架构分层图 —— 锚点：架构图
5. MVP 的五个关键结论 —— 编号列表 —— 锚点：结论
6. V2.0：三天引擎地基 —— 三阶段卡片 —— 锚点：采样统计数字
7. V2.1：Web 评测工作台 —— 产品结构图（7 视图 + API + 引擎）—— 锚点：结构图
8. V2.1：四类缺陷修复 —— 2×2 对比卡 —— 锚点：修复对比
9. V2.2：增强四件事 —— 四卡片 —— 锚点：LLM-as-a-Judge 判分示意
10. 验证结果 —— 大数字 + 表格 —— 锚点：大数字
11. 技术亮点与经验沉淀 —— 要点 + 一句引用 —— 锚点：引用句
12. 边界与未来 —— 未做项 + 展望路线 —— 锚点：路线
13. 结尾 —— 收束 + 仓库 —— 锚点：仓库地址

## 事实数据（验收用，全部来自真实项目）
- pytest：43（MVP 基线）→ 56（V2.1）→ 67（V2.2）全绿
- MVP：一周，5 任务（L1-L5）× 2 后端（minimal-react / aider），CLI + 自包含 HTML 报告
- V2.0：3 天（框架自测 / 命令沙箱 / 多 run 采样 --runs N + best/mean/std）
- V2.1：FastAPI + 原生 JS SPA + SQLite；7 视图；修复 4 类缺陷（PEP604 类型 / SQLite 跨线程 / run_id 不一致 / 前端引号白屏）
- V2.2：LLM-as-a-Judge（T502 真实判分 6/6，score 0.92，rubric 可配）；Langfuse 可选 trace；T601（3/3，score 1.0）；一键启动（workbench / bat / PyInstaller）
- 任务包：6 任务；引擎 100% 复用零重写
